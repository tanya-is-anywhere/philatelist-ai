# План к готовому продукту (полноценный MVP в итоге)
### Этап 1. Инфраструктура и «Скелет» приложения (Неделя 1)
На этом этапе мы поднимаем окружение, чтобы у всех членов команды локально всё запускалось, и связываем фронтенд с бэкендом базовым запросом.

- [ ] **Инфраструктура (Docker):** Настроить `docker-compose.yml` (PostgreSQL + PgVector). Убедиться, что база поднимается.
- [ ] **Backend (FastAPI):** Настроить `main.py`, `config.py` и базовый роут `/health` (проверка жизнеспособности). Подключить SQLAlchemy к БД.
- [ ] **Frontend (React):** Инициализировать Vite-проект внутри папки `frontend`, установить зависимости (`package.json`, `package-lock.json`), проверить работу папок FSD.
- [ ] **Связка:** Настроить базовый `axiosInstance.ts`. Сделать тестовый запрос с фронтенда на бэкенд (например, чтобы на главной странице выводился статус "Сервер работает").

> **Сигнал к переходу (Definition of Done):** Вы клонируете репозиторий на чистую машину, выполняете 3 команды (поднять докер, запустить бэк, запустить фронт) — и видите работающую страницу, которая успешно общается с базой данных через API. Ошибок в консоли нет.

### Этап 2. Безопасность и Авторизация (Неделя 2)
Закрываем приложение "на замок". Здесь мы реализуем ту самую сложную логику с JWT и hCaptcha, чтобы на защите было что показать.

- [ ] **Backend:** Создать модели `User` и `RefreshSession` в БД. Настроить миграции Alembic.
- [ ] **Backend:** Написать логику хеширования паролей (`passlib`), генерацию JWT (`PyJWT`) и ротацию Refresh-токенов.
- [ ] **Backend:** Подключить `captcha_service.py` (валидация hCaptcha через `httpx`) в роуты регистрации/входа.
- [ ] **Frontend:** Сверстать формы Входа/Регистрации по твоим макетам.
- [ ] **Frontend:** Подключить виджет `@hcaptcha/react-hcaptcha`.
- [ ] **Frontend:** Настроить перехватчики (interceptors) в Axios: если Access-токен протух (401), автоматически дергать `/refresh` и повторять запрос.

> **Сигнал к переходу:** Пользователь может зарегистрироваться (с прохождением капчи), войти в систему, а при обновлении страницы его сессия сохраняется (за счет refresh-токена). Если access-токен удалить из памяти, он автоматически обновится.

### Этап 3. Ядро ИИ и Бэкенд-логика (Недели 3-4)
Самый наукоемкий этап. Мы готовим ИИ-модуль и учим бэкенд обрабатывать фотографии.

- [ ] **AI/ML:** Подготовить датасет марок. Обучить (или дообучить) модель YOLOv8 для детекции марок.
- [ ] **AI/ML:** Настроить модель-экстрактор (DINOv2) для получения эмбеддингов. Загрузить эталонные марки в PgVector.
- [ ] **Backend:** Написать `file_handler.py` для безопасного сохранения загруженных фото.
- [ ] **Backend:** Связать ИИ-модуль с API. Создать роут `/recognize`. Он должен: принять фото -> прогнать через YOLO -> вырезать марки -> сделать эмбеддинги -> найти в PgVector -> вернуть JSON со списком марок (ID, координаты bbox, название, цена).
- [ ] **Backend:** *Временное решение (моки)*: если ИИ еще не готов, сделать заглушку, которая возвращает заранее заготовленный JSON для тестирования фронтенда.

> **Сигнал к переходу:** Через Swagger UI (`/docs`) вы загружаете фотографию с марками и получаете в ответ корректный JSON, где перечислены все марки на фото с их координатами (bounding boxes) и ценами.

### Этап 4. Главный пользовательский путь (UX/UI) (Неделя 5)
Оживляем кастомный дизайн. Это этап, где продукт начинает выглядеть как готовое приложение.

- [ ] **Frontend:** Сверстать экран загрузки (Drag & Drop зона, выбор камеры).
- [ ] **Frontend:** Сверстать экран обработки (анимация сканирования, прогресс-бар).
- [ ] **Frontend:** Сверстать экран результатов. Самое важное: сделать SVG-оверлей, чтобы поверх загруженной картинки рисовались рамки (bbox) найденных марок.
- [ ] **Frontend:** Вывести список карточек `StampCard` с ценами и итоговую сумму.
- [ ] **Frontend:** Связать экран загрузки с API `/recognize` (используя TanStack Query для обработки состояний загрузки/ошибки).

> **Сигнал к переходу:** Вы загружаете реальное фото листа с марками, видите красивую анимацию загрузки, а затем — экран результатов, где на фото подсвечены марки, а в списке выведены их названия и общая стоимость.

---

### Этап 5. Личный кабинет и Коллекция (Неделя 6)
Добавляем ценность для возврата пользователей. Продукт перестает быть одноразовым инструментом.

- [ ] **Backend:** Создать эндпоинты для добавления марки в коллекцию пользователя и получения списка его марок.
- [ ] **Frontend:** На экране результатов добавить кнопку "Сохранить в коллекцию" (срабатывает API-запрос).
- [ ] **Frontend:** Сверстать Дашборд коллекции (общая стоимость, количество марок).
- [ ] **Frontend:** Сверстать таблицу/сетку всей коллекции с фильтрами (по стране, году, цене).
- [ ] **Frontend:** Добавить в профиль настройки (смена валюты, выход из аккаунта).

> **Сигнал к переходу:** Пользователь может распознать марки, нажать "Сохранить", перейти в раздел "Моя коллекция", увидеть там эти марки и суммарную стоимость своего собрания.

---

### Этап 6. Полировка, Тестирование и Защита (Неделя 7)
Финальный рывок. Убираем шероховатости, пишем тесты и готовим демо.

- [ ] **Frontend:** Отрисовать все состояния: пустые экраны ("У вас пока нет марок"), экраны ошибок ("Не удалось распознать"), скелетоны загрузки. Проверить адаптив под мобильные телефоны.
- [ ] **Тестирование:** Написать базовые тесты на бэкенд (Pytest) для проверки авторизации и роута `/recognize` (с моками ИИ).
- [ ] **Тестирование:** Пройтись по всему приложению вручную, найти и исправить баги.
- [ ] **Документация:** Дописать `README.md` (добавить финальные инструкции по запуску).
- [ ] **Подготовка:** Записать демо-видео или подготовить сценарий показа для преподавателя/комиссии.

> **Сигнал к переходу (ФИНАЛ MVP):** Приложение работает стабильно от и до. Вы нажимаете "Поделиться экраном" на защите и без запинок проходите путь: Регистрация -> Вход -> Загрузка фото -> Результат -> Сохранение в коллекцию. Все чек-листы закрыты.

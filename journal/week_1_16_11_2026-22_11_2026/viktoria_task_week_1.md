### Ход работы:

#### Задача 1. Настройка Alembic (миграции БД)
**Что нужно сделать:** Инициализировать Alembic в проекте и настроить его так, чтобы он видел твои модели.
**Для чего это нужно:** Alembic автоматически создает и обновляет таблицы в базе данных на основе Python-кода.
**Шаги выполнения:**
1. В терминале (в папке `backend`, с активированным `venv`) выполни: `alembic init alembic`.
2. Открой файл `backend/alembic/env.py`. Найди строку `target_metadata = None` и замени её на:
   `from app.db.base import Base`
   `import app.db.models`
   `target_metadata = Base.metadata`
3. В том же файле `env.py` настрой подключение к БД. Alembic должен брать URL из твоего `config.py` (используй `settings.DATABASE_URL`).

#### Задача 2. Создание таблиц в PostgreSQL
**Что нужно сделать:** Сгенерировать миграцию и применить её к базе.
**Для чего это нужно:** Чтобы в PostgreSQL появились реальные таблицы `users` и `refresh_sessions`.
**Шаги выполнения:**
1. В терминале выполни: `alembic revision --autogenerate -m "create users and sessions tables"`.
2. Если ошибок нет, выполни: `alembic upgrade head`.
3. Открой DBeaver (или попроси Демида), подключись к базе `philatelist_db` и проверь, что таблицы появились.
4. Сделай скриншот таблиц (это понадобится для отчета).

#### Задача 3. Написание утилит безопасности (`security.py`)
**Что нужно сделать:** Написать функции для хеширования паролей и создания JWT-токенов.
**Для чего это нужно:** Мы не храним пароли в открытом виде, а токены нужны для авторизации пользователя.
**Шаги выполнения:**
1. Открой файл `backend/app/core/security.py`.
2. Добавь функцию `get_password_hash(password: str) -> str` с использованием `passlib.context.CryptContext` (схема bcrypt).
3. Добавь функцию `verify_password(plain_password: str, hashed_password: str) -> bool`.
4. Добавь функцию `create_access_token(subject: str)`. Используй `PyJWT`, укажи время жизни из `settings.ACCESS_TOKEN_EXPIRE_MINUTES`. Не забудь указать алгоритм (`HS256`).

#### Задача 4. Создание Pydantic-схем для валидации
**Что нужно сделать:** Описать схемы данных для регистрации и входа.
**Для чего это нужно:** FastAPI должен проверять, что фронтенд присылает правильные данные (например, чтобы email был почтой, а пароль не был пустым).
**Шаги выполнения:**
1. Открой файл `backend/app/db/schemas.py`.
2. Создай класс `UserCreate(BaseModel)`: поля `email` (тип `EmailStr`), `password` (тип `str`, минимум 8 символов).
3. Создай класс `UserResponse(BaseModel)`: поля `id` (UUID), `email`, `is_active`. В настройках модели укажи `model_config = ConfigDict(from_attributes=True)`.

#### Задача 5. Написание эндпоинта `/register` (Регистрация)
**Что нужно сделать:** Создать API-метод, который принимает email и пароль, создает пользователя и сохраняет его в БД.
**Для чего это нужно:** Это точка входа для новых пользователей.
**Шаги выполнения:**
1. Открой файл `backend/app/api/v1/auth.py`.
2. Создай `@router.post("/register", response_model=UserResponse)`.
3. Внутри функции проверь, существует ли пользователь с таким email в БД. Если да — верни ошибку `400 Bad Request`.
4. Если нет — захешируй пароль через функцию из Задачи 3, создай объект `User` и сохрани его (`db.add(user); db.commit(); db.refresh(user)`).
5. Верни созданного пользователя.

#### Задача 6. Написание эндпоинта `/login` (Вход)
**Что нужно сделать:** Создать API-метод для входа пользователя и выдачи токена доступа.
**Для чего это нужно:** Чтобы пользователь мог авторизоваться и получать доступ к защищенным страницам.
**Шаги выполнения:**
1. В том же файле `auth.py` создай `@router.post("/login")`.
2. Прими на вход схему с email и паролем (создай `UserLogin` в `schemas.py`).
3. Найди пользователя в БД по email.
4. Проверь пароль через `verify_password`. Если неверный — верни ошибку `401 Unauthorized`.
5. Если всё ок — сгенерируй `access_token` и верни его в JSON: `{"access_token": token, "token_type": "bearer"}`.

#### Задача 7. Создание скелета `captcha_service.py` и отправка PR
**Что нужно сделать:** Создать заготовку для будущей проверки hCaptcha и отправить весь код на проверку.
**Для чего это нужно:** На следующей неделе мы будем подключать капчу к формам, нужно подготовить для этого место в коде.
**Шаги выполнения:**
1. Создай файл `backend/app/services/captcha_service.py`.
2. Напиши функцию-заглушку `async def verify_captcha(token: str) -> bool:`, которая пока просто возвращает `True` (реальную интеграцию сделаем на следующей неделе).
3. Запусти сервер: `uvicorn app.main:app --reload`.
4. Открой `http://localhost:8000/docs` и протестируй `/register` и `/login`.
5. Сделай коммит и пуш в свою ветку `backend`.
